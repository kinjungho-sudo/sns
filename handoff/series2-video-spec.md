# 시리즈 2 「AI 업무 자동화」 영상 설계서 (PC 제작용)

> 이 문서는 클라우드 세션에서 설계하고, **PC의 Claude Code**에서 제작하기 위한 인계 문서입니다.
> 원고(나레이션·화면 문구·결과물 데이터)는 이 문서에 없고, 사용자가 제작 세션에 따로 전달합니다.

---

## 0. 제작 세션에 붙여넣을 지시문

```text
첨부한 설계서(series2-video-spec.md)대로 시리즈 2 「AI 업무 자동화」 EP.__ 영상을 만들어줘.
원고는 바로 아래에 붙여넣을게.

1. 원고를 설계서 3장의 "원고 형식"에 맞춰 장면별로 정리하고, 빠진 항목이 있으면 만들기 전에 물어봐.
2. 이 프로젝트에 이미 있는 렌더 방식(Remotion·HyperFrames·HTML 캡처 등)을 그대로 쓰되, 설계서의 규격·디자인·모션·오디오 규칙을 지켜.
3. 나레이션은 타입캐스트로 만들고(설계서 7장), 영상 길이는 실제 나레이션 길이에 맞춰.
4. 목소리는 내가 고를 수 있게 한국어 목소리 후보 3개를 먼저 보여줘(유료 생성 전 확인).
5. 15초 미리보기 → 확인 → 최종 렌더 순서로 진행하고, 설계서 10장 체크리스트로 검수한 결과를 알려줘.
6. AutoFlowCut이 켜져 있으면 설계서 9장대로 CapCut 프로젝트까지 내보내줘.

[원고]
(여기에 붙여넣기)
```

## 1. 이 시리즈의 원칙 (반드시 지킬 것)

| 항목 | 규칙 |
|---|---|
| 채널 목적 | "누구나 끝까지 따라올 수 있는 AI 교육을 하는 사람"(CoMindWorks). 타깃은 **직장인** |
| 서사 | 실제 업무의 고통(Before) → 30초 결과물(After). **결과물을 먼저** 보여준다 |
| 톤 | 친근하고 쉽게, 진짜 따라 할 수 있게. 과장·허세 금지 |
| 결과물 표현 | 생 스크린샷도 가짜 UI도 아닌, **실제 출력을 브랜드 디자인으로 깔끔하게 재현** |
| 이름 | 화면에 **실명 금지**. 역할명(팀장·담당자·기획·영업 등)으로 표기 |
| 푸터 | **CoMindworks만** (`Co` + 러스트 `Mind` + `works`). @핸들·개인명 금지 |
| 캐릭터 | Parro 캐릭터 등장 금지 |
| 프롬프트·양식 | **화면에 넣지 않음**. 댓글 키워드로 배포(배포자료) |
| 검증 | 실제로 돌려서 같은 결과가 재현되는 것만 올림. 영상 속 결과물 데이터는 실제 출력에서 가져옴 |
| 장면당 메시지 | 1개. 화면 글자는 장면당 30단어 이하 |

## 2. 산출물

| 파일 | 규격 |
|---|---|
| `EPNN_<주제>.mp4` | **1080×1350 (4:5 피드형)**, 30fps, H.264(yuv420p, CRF 18) + AAC 192k, `+faststart` |
| `cover.png` | 1080×1350. 훅 장면이 다 나온 순간(약 3초) |
| `EPNN_<주제>.srt` | 나레이션 문장 단위 자막 (UTF-8) |
| `캡션.txt` | 게시 캡션: 훅 → 공감 → 핵심 3줄(✔) → 3단계 → 댓글 키워드 CTA → 팔로우. 해시태그 10개 내외, @핸들 없음 |
| `배포자료/` | 프롬프트.md(순서·전제조건·자주 막히는 곳), 양식 파일 |
| CapCut 프로젝트 | (선택) 9장 절차로 내보내기 |

길이는 나레이션에 맞춰 정해지며 보통 **40~55초**입니다. 너무 빠르다는 피드백이 있었으니 줄이려고 서두르지 않습니다.

## 3. 원고 형식 (사용자가 줄 원고를 이 틀로 정리)

장면은 5개이고, 각 장면에 **나레이션 1~3문장**과 **화면 문구**가 있습니다.

```yaml
ep: EP.05
topic: <짧은 주제, 예: 회의록 정리>          # 상단 태그 옆에 표시
keyword: <댓글 키워드, 예: 회의록>
result_frame: 표형 | 문서형 | 대화형 | 화면형 | 설정형   # 5장 참고

scenes:
  - type: hook
    vo: "<나레이션>"                       # 읽을 문장 (자막도 이 문장)
    headline: "<2줄 이내, 강조어 1개 표시>"   # 예: "회의 메모,\n[30초]면 회의록"
    sub: "<한 줄 보조문>"
    flow: [<원본 입력>, Claude, <결과물>]    # 입력칩 3개

  - type: before
    vo: "<나레이션>"
    headline: "<2줄>"
    mess: <지저분한 원본의 실제 내용: 메모 줄 / 영수증 / 파일 목록 등>
    timer: "<예: 정리 중… 40분째>"

  - type: result                          # 빈 양식 → 채워진 결과물
    vo: "<나레이션 (가장 김)>"
    frame_headline: "우리 회사 양식,\n[그대로] 넣으세요"
    after_headline: "<예: 메모 던지고\n[30초] 뒤>"
    data: <실제 출력 결과: 표 행 / 문서 섹션 / 대화 / 설정 노드>
    status: { working: "Claude가 … 읽는 중…", done: "✓ 완료 · NN초" }
    stamp: { big: "30초", small: "정리 끝" }

  - type: steps
    vo: "<나레이션>"
    steps: [ {title, desc} ×3 ]
    note: "<전제조건 또는 안심 문구 1줄>"

  - type: cta
    vo: "<나레이션: 댓글 키워드 안내>"
    box: { k: "양식 + 프롬프트 바로 보내드려요", d: "<한 줄>" }
    follow: "팔로우하면 매일 1편, 업무 자동화"
```

원고에 화면 문구가 없으면 나레이션에서 뽑아 제안하고, 확인을 받은 뒤 만듭니다.

## 4. 영상 구조와 타이밍

### 4-1. 장면 흐름 (7장 캐러셀 → 5장면)

| # | 장면 | 원래 카드 | 화면 연출 |
|---|---|---|---|
| 1 | hook | 표지 | 큰 헤드라인과 강조어 밑줄 그리기 → 완성된 결과물 일부를 기울인 카드로 미리보기 → 입력칩 3개 (원본 → **Claude** → 결과물) |
| 2 | before | Before | 지저분한 원본이 하나씩 떨어지며 쌓임 → 좌하단 "⏱ 정리 중… N분째" 카운터가 올라감 |
| 3 | result | 핵심 + After | ① 빈 양식 카드 등장(헤드라인 "우리 회사 양식, 그대로 넣으세요") → ② 헤드라인이 After로 교체되고 상태칩 "Claude가 … 읽는 중…" → ③ 항목이 **한 줄씩** 채워짐(타이핑·숫자 카운트업·행 하이라이트) → ④ 합계·완료 → ⑤ "30초" 도장이 찍힘 |
| 4 | steps | 3단계 + 요약 | 번호 카드 3개가 오른쪽에서 차례로 들어옴 + 하단 note |
| 5 | cta | CTA | 큰 헤드라인 "댓글에 '키워드'" → 댓글 입력창에 키워드가 타이핑됨 → 배포 안내 박스 → 팔로우 줄. 마지막 화면 유지 |

### 4-2. 속도 규칙 (중요: "너무 빠르다" 피드백 반영)

- **모든 움직임을 기본 대비 1.3배 느리게** 합니다(전체 pace 1.3).
- 장면 길이는 `max(최소 길이, 나레이션 시작 지연 0.35s + 나레이션 길이 + 여유 0.6s)`로 잡습니다. 마지막 장면만 여유를 0.8s 더 줍니다.
- 애니메이션이 먼저 끝나면 **완성된 화면을 나레이션이 끝날 때까지 유지**합니다. 새 요소로 채우지 않습니다.
- 장면 퇴장은 마지막 0.35s 동안 위로 살짝 흐려지며 사라집니다(아래 6장).

### 4-3. 장면별 최소 길이 (pace 적용 전, 초)

| hook | before | result | steps | cta |
|---|---|---|---|---|
| 3.4 | 3.8 | 9.0~10.2 | 3.8 | 3.0~3.4 |

result 장면 안 세부 타이밍(장면 시작 기준, pace 적용 전): 빈 양식 0.35s 등장 → 2.6s에 After로 교체 → 3.2s부터 항목 채우기(행 간격 0.55s, 문서형은 0.36s) → 완료 후 0.2s 뒤 도장.

## 5. 결과물 프레임 (주제에 맞게 1개 선택)

| 프레임 | 맞는 주제 | result 장면 구성 |
|---|---|---|
| **표형** | 지출결의서, 엑셀, 리서치 표 | 제목 + 메타(소속·작성자) + 결재란(선택) + 표(헤더 진한색) + 합계 행(러스트, 카운트업). 계정과목 같은 분류값은 연한 러스트 pill |
| **문서형** | 회의록, 보고서, 견적서 | 문서 제목(자간 넓게) + 정보 행(회의명·일시·참석) + 번호 섹션(결정 사항 / 미정 / 조치 표). 원문에 없는 값은 **"확인 필요" 러스트 태그** |
| **대화형** | 메일, 번역, 프롬프트 | 실제 AI 대화를 브랜드 말풍선으로 재현. 핵심 한 줄만 하이라이트 |
| **화면형** | 일정, 차트, 대시보드 | 브라우저 또는 폰 프레임 + 크림 배경 + 그림자 |
| **설정형** | 스킬, 예약 실행, n8n | 워크플로 노드 카드 + 핵심 노드 강조 + 연결선이 그려짐 |

공통: 여백은 정리하고 핵심만 보이게, 부드러운 배경과 그림자, 콜아웃은 1개만 씁니다.

### 6-2. 글꼴
- **A2Z**를 우선 쓰고, 없으면 Pretendard로 대체합니다(9웨이트).
- 헤드라인은 900(Black), 본문은 500/600, 숫자는 tabular-nums를 씁니다.
- 줄바꿈은 `word-break: keep-all`(한국어 단어 단위)입니다.

### 6-3. 레이아웃 (1080×1350 기준)
- **좌우 여백 80px.**
- **상단 고정(64px):** 러스트 pill "AI 업무 자동화"(26px, 800) + 회색 "EP.NN · 주제"
- **하단 고정(56px):** 왼쪽 로고 `Co**Mind**works`(30px, 800, Mind만 러스트), 오른쪽 진행바(260×8px, 러스트 채움)
- **본문 영역:** 위 170px ~ 아래 150px
- **헤드라인:** 92px / 행간 1.18 / 자간 -3px. 훅·CTA는 118px. 위에 라벨(26px, 800, 자간 3px, 러스트, 예: BEFORE · 핵심 · AFTER · HOW · 무료 배포)
- **결과물 카드:** 좌우 80px, 위 455~470px부터. 하단 로고와 겹치지 않게 1240px 안에서 끝냅니다.
- **"30초" 도장:** 210px 원, 러스트 7px 테두리, 오른쪽 위(약 x790, y195), -12° 회전

### 6-4. 컴포넌트
- **종이 카드:** paper, 모서리 28px, 그림자 `0 24px 60px -18px rgba(42,36,31,.28)`
- **입력칩:** pill, 2px line 테두리, 아이콘(러스트 선) + 30px 텍스트. 가운데 칩(Claude)은 러스트 채움
- **상태칩:** ink 배경 pill + 회전 스피너 → 완료 시 러스트 배경 "✓ 완료 · NN초"
- **영수증·메모 같은 원본:** 실제 종이 질감(영수증은 아래 톱니, 메모는 줄 노트), 살짝 기울임
- **댓글 입력창:** 원형 아바타 + 키워드 타이핑 + 깜빡이는 커서 + 러스트 "게시"

## 7. 모션 규칙

- **결정적 렌더링:** 프레임 t를 지정하면 항상 같은 화면이 나와야 합니다(무작위·실시간 시계 금지). 프레임 단위로 캡처하거나 Remotion의 frame 기반으로 만듭니다.
- **이징:** 기본 `cubic-bezier(.16,1,.3,1)`, 튕김 `cubic-bezier(.34,1.56,.64,1)`, 교체 `cubic-bezier(.65,0,.35,1)`
- **등장:**
  - 위로 떠오르기: 40~50px, 0.6~0.7s
  - 팝: scale .6→1, 0.45~0.5s, 튕김
  - 영수증 낙하: -420px에서 회전하며 0.5s, 0.3s 간격
- **강조어 밑줄:** 헤드라인 등장 0.55s 뒤 0.5s 동안 왼쪽→오른쪽
- **타이핑:** 표 셀 약 30~40자/초, 댓글 키워드 8자/초. **루프 안에서 시작 시각을 상수로 고정**합니다. 바뀌는 변수를 참조하면 글자가 늦게 뜨는 버그가 납니다.
- **숫자 카운트업:** ease-out cubic, 0.4~0.8s, 천 단위 쉼표
- **행 하이라이트:** rsoft가 0→1→0으로 1.0s(처음 15% 지점이 최고)
- **장면 퇴장:** 마지막 0.35s 동안 opacity 1→0, y -24px, blur 0→6px
- **진행바:** 영상 전체 진행률

## 8. 오디오

### 8-1. 나레이션 (타입캐스트)

| 설정 | 값 |
|---|---|
| 엔드포인트 | `POST https://api.typecast.ai/v1/text-to-speech/with-timestamps?granularity=word` (음성 base64 + 단어별 시작·끝 시각) |
| 인증 | 헤더 `X-API-KEY` (PC의 `cast login` 키 또는 `TYPECAST_API_KEY`). 키는 채팅·파일·로그에 남기지 않음 |
| 모델 | `ssfm-v30` |
| 감정 | `prompt: { emotion_type: "smart", previous_text, next_text }`: 앞뒤 장면 문장을 함께 넘겨 이어지는 말투로 |
| 출력 | `output: { audio_format: "wav", audio_tempo: 1.0, remove_silence_ms: 300, target_lufs: -16 }`, `language: "kor"` |
| 단위 | **장면당 1요청** (장면 길이를 나레이션에 맞추기 위해) |
| 캐시 | 원고·목소리·설정이 같으면 재생성하지 않음(유료) |
| 출처 표시 | 요청 User-Agent 끝에 `typecast-integration/1 (source=api-page; generated_by=claude-code)` |
| 대안 | `cast` CLI: `cast "<문장>" --voice-id … --language kor --tempo 1.0 --remove-silence-ms 300 --format wav --out NN.wav --timestamp-out NN.srt` (환경변수 `TYPECAST_INTEGRATION_SOURCE=api-page`, `TYPECAST_GENERATED_BY=claude-code`) |

**읽기용 변환:** 화면과 자막은 원고 그대로 두고, 타입캐스트에 보내는 문장만 바꿉니다.
- `30초` → `삼십 초`, `40분` → `사십 분`, `Claude` → `클로드`, `ChatGPT` → `챗지피티`
- 금액·날짜는 한글 숫자로 바꿉니다.

**목소리:** 사용자가 고른 voice_id를 씁니다. 정해지지 않았으면 한국어 목소리 후보 3개를 제시하고 확인받습니다.

### 8-2. BGM (밝은 느낌)

| 항목 | 값 |
|---|---|
| 템포·조성 | **108bpm, D장조**, 진행 D – A – Bm – G (마디마다) |
| 악기 | 어쿠스틱 기타 스트럼(플럭), 베이스, 글로켄 멜로디, 킥(1·3박)·클랩(2·4박)·셰이커(16분) |
| 페이드 | 시작 0.3s 인, 끝 1.5s 아웃 |
| 덕킹 | 나레이션 구간에서 BGM을 **약 -10dB**(0.3배)로 낮춤. 앞뒤 0.2s 램프 |
| 대안 | 저작권 걱정 없는 음원을 쓰면 -14dB로 깔고 같은 덕킹 적용 |

### 8-3. 효과음 (나레이션이 있을 때는 60% 볼륨)

| 소리 | 시점 |
|---|---|
| whoosh | 장면 전환 |
| pop | 카드·칩·태그 등장 |
| drop | 원본(영수증·메모)이 떨어짐 |
| type | 행 채우기, 댓글 타이핑 (짧은 키 클릭 4번) |
| ding | 합계·완료 |
| stamp | 30초 도장 |

### 8-4. 최종 믹스
- 피크 -1dBFS 이하, 전체 약 -16 LUFS
- 나레이션이 가장 잘 들려야 합니다.

## 9. CapCut으로 내보내기 (AutoFlowCut, 선택)

AutoFlowCut 앱이 PC에서 실행 중이고 MCP(`flow2capcut`)가 등록돼 있을 때만 합니다.

1. **컷 만들기:** 나레이션 **문장 1개 = 컷 1개**. 컷 이미지는 영상에서 그 문장이 끝나는 순간의 프레임(jpg)이고, 장면 퇴장 직전 시점으로 잡습니다.
2. **번들 폴더:**
   - `scenes.csv`: 열은 `prompt, prompt_ko, subtitle, shot_type, duration, start_time, end_time, parent_scene`. UTF-8 BOM. prompt는 영문 설명
   - `scenes/scene_N.jpg`
   - `media/narration.wav`: 장면별 음성을 영상 시각에 맞춰 이어 붙인 것
   - `media/narration.srt`: 문장 단위
   - `media/sfx/bgm_0000.wav`: BGM과 효과음
3. **MCP 순서:**
   1. `app_status`
   2. `app_create_project({name})` → 응답 경로에 번들 복사
   3. `load_csv({csv_path, image_dir: 프로젝트경로})`
   4. `list_scenes`로 확인
4. **오디오 연결:** 앱 화면의 오디오 패널 → 폴더 가져오기. 사용자가 직접 눌러야 합니다.
5. **내보내기:** `export_capcut({ includePending: true, videoAudioVolume: 0 })`

결과물이 보이는 컷은 AI 이미지로 바꾸지 않습니다(시리즈 원칙).

## 10. 검수 체크리스트

- [ ] 1080×1350, 30fps, H.264 + AAC, 길이가 나레이션 끝 + 약 1초
- [ ] 모든 장면에서 나레이션이 끝난 뒤에 장면이 넘어간다(말이 잘리지 않음)
- [ ] 화면 글자가 장면당 30단어 이하이고, 로고·상단 태그와 겹치지 않는다
- [ ] 결과물 데이터가 실제 출력과 같다(숫자·합계·날짜 일치)
- [ ] 실명·@핸들·Parro·프롬프트 원문이 화면에 없다
- [ ] 타이핑 중간 프레임에서 글자가 비거나 늦게 뜨지 않는다(중간 시점 스틸 3장 이상 확인)
- [ ] 숫자·영문 발음이 자연스럽다(30초, Claude 등)
- [ ] BGM이 나레이션을 가리지 않는다(덕킹 확인), 피크 -1dBFS 이하
- [ ] 자막(.srt) 시간이 실제 말과 맞는다
- [ ] 접촉 시트(장면별 스틸 8장 정도)를 사용자에게 보여주고 확인받았다
